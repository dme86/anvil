# Anvil v0.7.0 — smoother everyday use, less repeated work

Anvil keeps its keyboard-driven desktop, independent layouts per tag, floating
windows, app launcher, window overview and scriptable bar. This release improves
how those features use rendering time and memory.

## A smoother desktop

- Opening and closing windows keeps existing window contents visible while apps
  prepare their new buffers, avoiding a brief flash of wallpaper during layout
  changes.
- Rapid mouse movement follows each display's refresh rate instead of submitting
  redundant frames. Input handling stays responsive, and the final movement is
  still drawn when input stops.
- Floating moves and resizes update the affected window directly. Unchanged
  windows keep their layout and stacking state.
- Static bar contents and overview labels reuse their completed rendering.
  Overview previews remain live, including apps whose contents change while the
  overview is open.

## Fonts and memory

- The bar, launcher and overview share font faces and bounded glyph caches.
  FreeType loads outlines on demand instead of eagerly retaining every glyph in
  large fonts.
- Fontconfig resolves fallback glyphs and font-collection faces consistently for
  measurement and drawing. A patched Nerd Font is optional; a separate symbols
  font can supply status icons.
- Different faces in one TTC/OTC font collection share the same file bytes.
  Character-to-glyph indices use compact storage, while the hot glyph cache and
  all supported font/fallback behavior remain available.
- Temporary GPU readback resources are cleaned up at the end of capture-only
  passes, without requiring another screen redraw.
- The ordinary one-window Gentoo VM remained around 102 MiB RSS. In one matched
  screenshot-then-idle sample, RSS was approximately 110 MiB before and 106 MiB
  after. These figures depend on the renderer, allocator and workload; this is
  not a universal RAM budget. See the [memory measurements](../memory-usage.md).

## Multiple monitors and screen capture

Parallel modern image-copy and legacy screencopy requests share a render/readback
when they capture the same monitor with the same cursor setting. Cropped images
copy directly from the mapped pixels without an extra full-screen CPU image.
Images are never reused across different monitors or later frames.

In the three-monitor Gentoo VM test, 48 completed images used eight GPU readbacks.
A separate screenshot required one readback and no additional scanout render
attempts or submissions. These are workload-specific shared-work counts, not a
promise of a particular FPS or CPU usage.

## Responsive helpers and installation

- Launcher indexing, status/network helpers and local control transport avoid
  blocking the compositor loop. Incomplete IPC requests still receive a proper
  timeout error.
- Idle notification timers are reused across input activity.
- `rst` is the default terminal command; configure `general.terminal` to use a
  different installed terminal.
- The documented Makefile supports normal, minimal and custom feature builds
  with staged installation.

The release workflow runs Rust tests, Clippy, feature-profile builds, real nested
Wayland protocol tests and footprint checks before publishing the Linux x86_64
archive and checksum. Gentoo aarch64 users should build locally with
`make build` and install using `sudo make install`.
