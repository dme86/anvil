# Anvil v0.6.4 — XWayland surface association race

This patch fixes the intermittent X11 window mapping failure tracked in [#70](https://github.com/dme86/anvil/issues/70).

## Root cause and fix

Smithay can associate an X11 window with its Wayland surface in either event order:

- **X11 first:** the Wayland surface commits after the X11 serial; Smithay calls `surface_associated` on Anvil.
- **Wayland first:** the X11 `WL_SURFACE_SERIAL` arrives after the Wayland surface committed; Smithay calls `surface_associated` on CalloopData.

Anvil handled the first callback but accidentally left the CalloopData implementation at its default no-op. Depending on event ordering, an otherwise mapped X11 window would therefore never enter Anvil's managed window list. Forward the CalloopData association callback to Anvil's existing idempotent window registration logic. The earlier `MapNotify` handling remains in place.

## Regression coverage

The real nested XWayland integration test now exercises eight X11 map/unmap cycles before starting its existing native Wayland coexistence, XWayland server-crash cleanup, focus recovery and native-client restart checks. The test's mapping and crash assertions are preserved; they are not suppressed or given a longer timeout.

XWayland remains an **opt-in compile-time Cargo feature** and an **opt-in runtime compatibility service**. Default builds and native Wayland sessions are unaffected.
