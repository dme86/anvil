# Anvil v0.6.7 — your layout, on every tag

Anvil now remembers the selected layout **per tag, per monitor** (inspired by dwm's pertag patch).

- On Tag 1, stay with Tiling. On Tag 2, switch to Monocle. On Tag 3, switch to Floating. Changing tags automatically restores their separate layout modes.
- **Super+Space** or clicking the bar's layout symbol changes only the currently viewed tag; every other tag is unaffected.
- Each output stores its own layout choices. For a view with multiple selected tags, the **lowest numbered selected tag** determines the effective layout.
- The bar displays the selected tag's layout symbol. Floating move/resize, window lists and normal focus behavior all use the effective per-tag mode.
- Layout choices survive reloads, window movement, output mode/size changes and hiding the bar. A newly connected output starts with default Tiling modes. Runtime layout choices are not written to disk.
- Invalid/higher selected tags are masked safely if a configuration reload reduces `general.tags`; saved modes remain for a later increase.

## Resource impact

The previous single `LayoutMode` per output is replaced by a fixed **nine-element inline array**. There are no extra threads, files, timers, subscriptions, commands or periodic checks, so this feature adds **no new idle work**. Runtime memory grows by only a few bytes per connected output, not per window or frame. GitHub CI validates the build profiles and Linux Wayland nested protocol tests. Actual CPU/RSS on specific DRM hardware or QEMU installations still require environment-specific measurements.

## Getting started

Use **Super+1**, then **Super+Space** to select your favorite layout. Switch to **Super+2**, choose a different mode, and return to Tag 1. Both tags remember their mode automatically. No config changes are required. See [README.md](../../README.md) for shortcuts and installation.

Linux binary releases may be x86_64-only; on aarch64 Linux build locally with `cargo build --release --locked`.
