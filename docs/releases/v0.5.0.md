# Anvil v0.5.0 — Configuration & Live Control

Anvil 0.5.0 makes configuring a Wayland desktop much more practical: inspect settings, edit them without losing comments, discover connected monitors, and apply supported changes without restarting the compositor.

This release also includes the diagnostics, recovery and regression-testing improvements developed for the v0.4.0 milestone. The previous published 0.x version was v0.3.3.

## Highlights

### A practical `anvilctl config` workflow

- Inspect the active configuration location with `anvilctl config path`; create a commented starter file with `config init` and optionally `--force`. Print the original TOML with `config show` and check it with `config validate`. These commands work offline. ([#24](https://github.com/dme86/anvil/issues/24), [PR #48](https://github.com/dme86/anvil/pull/48))
- Use `config get`, `config set` and `config unset` with dotted keys to make targeted changes. Optional `--reload` requests a live reload. ([#25](https://github.com/dme86/anvil/issues/25), [PR #50](https://github.com/dme86/anvil/pull/50))
- Changes preserve unrelated comments and TOML formatting; complete-config validation and same-directory atomic replacement protect existing files from partial writes. Existing file permissions are retained. ([#27](https://github.com/dme86/anvil/issues/27), [PR #49](https://github.com/dme86/anvil/pull/49))

### Monitor discovery and configuration

- `anvilctl output list` reports connected connector names, current/preferred modes and the effective position, scale and transform.
- `anvilctl output configure DP-1 --mode 2560x1440@144 --position 0,0 --scale 1.25 --transform normal` adds or updates one `[[outputs]]` entry, without duplicates.
- `anvilctl output reset DP-1` removes that output's explicit overrides. Configure/reset work offline; add `--reload` to attempt applying them immediately. ([#26](https://github.com/dme86/anvil/issues/26), [PR #51](https://github.com/dme86/anvil/pull/51))

### More dependable live reload

- Validate before changing active state; rejected config changes and restart-only settings produce an error instead of being silently ignored.
- Reapply supported DRM output mode, scaling, transform and position changes, update mouse and touchpad options on existing libinput devices, reflow displays and windows, and reevaluate window rules.
- Recalculate usable desktop area when the native bar's height changes. If a backend reconfiguration fails, keep the previous active config and attempt to restore backend state.
- Explicitly report settings that need a compositor restart, including keyboard seat changes, compatibility/startup options and selected bar settings. Nested sessions remain controlled by their host window. ([#28](https://github.com/dme86/anvil/issues/28), [PR #52](https://github.com/dme86/anvil/pull/52))

## Reliability improvements included since v0.3.3

The v0.4.0 development milestone added structured runtime diagnostics, nested compositor integration and lifecycle tests, stress and recovery test coverage, resource-usage regression checks, and binary-size/dependency footprint checks. These checks are part of CI for this release.

## Try the new commands

```sh
anvilctl config init
anvilctl config validate
anvilctl config get layout.gap
anvilctl config set layout.gap 12 --reload
anvilctl output list
anvilctl output configure DP-1 --scale 1.25 --reload
anvilctl output reset DP-1 --reload
```

The `anvilctl` binary requires the optional `anvilctl` Cargo feature (enabled by default). `output list` and live reload require a running compositor. Writes are persisted **before** an optional reload is attempted, and a failed reload does not undo the saved file.

## Package

The x86_64 Linux tarball contains `anvil`, `anvilctl`, a sample `config.toml`, the session file, README, license and notices. Verify the tarball against the accompanying `.sha256` file before installing.

**Testing note:** CI validates Rust builds and tests, Clippy, nested Wayland integration and size regression. Direct physical DRM/KMS hardware validation is **not yet complete** and remains tracked in [#47](https://github.com/dme86/anvil/issues/47). This is a pre-1.0 release.
