# Anvil v0.6.2 — Quieter idle compositor

Anvil v0.6.2 focuses on reducing avoidable idle work, particularly noticeable when running **x86_64 Linux under QEMU TCG** on Apple Silicon. The release includes two independent optimizations based on live guest diagnostics. CPU savings are **not yet quantified on the user's VM**; repeatable before/after measurements remain in [issue #63](https://github.com/dme86/anvil/issues/63).

## 1. Event-driven child process reaping ([PR #64](https://github.com/dme86/anvil/pull/64))

Previously, every event-loop iteration called `Child::try_wait()` on each still-running compositor-launched command. With four long-lived children (`mako`, `swaybg`, and two `alacritty` processes), an idle VM trace showed **1,230 `wait4(WNOHANG)` calls in six seconds**, despite no child exiting.

Now:
- Linux `pidfd_open` and Calloop report **actual child exit readiness**. Anvil reaps the child and removes its event watcher after the event; long-running children are not repeatedly polled.
- Older kernels or environments where pidfds are unavailable use a bounded **one-second fallback reaper**, retaining reliable zombie cleanup.
- Launches from startup commands, the launcher and `anvilctl` share this lifecycle behavior.
- Added a real child-exit/readiness test to prevent regressions.

## 2. On-demand direct DRM rendering ([PR #65](https://github.com/dme86/anvil/pull/65))

The direct DRM backend previously ran a periodic **16-ms repaint timer (~62.5 wakeups/s)** even when `repaint_requested == false`. Diagnostic counters confirmed just one submitted frame in more than 20 seconds of idle time, so this timer caused unnecessary checks rather than actual redraws.

Now:
- Client commits, input and compositor state changes issue a **coalesced Calloop wakeup** when a redraw is needed. Multiple requests before a dispatch are combined.
- KMS VBlank notifications wake up paint work waiting for a pending page flip.
- Transient render failures use a **100-ms delayed retry**, avoiding a tight GPU-error busy loop.
- Status-bar commands refresh on their **configured interval** (default one second), rather than being checked every 16 ms. Without the bar feature no status-bar timer is installed.
- The **nested Winit development backend** retains its separate host-window scheduler; this change targets the native Linux DRM/KMS path.

## Diagnostics and limitations

The investigation used a QEMU guest reporting ~6.05% of one virtual CPU while idle and ~47.9 thread context switches per second before these changes. This is an **emulated x86_64 TCG environment**, so the results should not be treated as a native-hardware baseline. No measured after-value or percentage improvement is claimed.

To check the runtime after installing v0.6.2:

```sh
anvilctl debug stats
pid=$(pgrep -xo anvil)
sudo timeout -s INT 6s strace -tt -e trace=wait4 -p "$pid"
```

In a modern kernel with `pidfd_open` support, long-running children should no longer generate repeated `wait4(..., WNOHANG)` calls. The actual idle CPU effect should be checked with the same fixed-duration `/proc/<pid>/stat` CPU tick benchmark used in issue #63.

Anvil remains a pre-1.0 compositor. CI covers Rust unit tests, Clippy, nested Wayland/XWayland protocols and feature/footprint profiles; **real DRM/KMS hardware regression testing** is still tracked in [issue #47](https://github.com/dme86/anvil/issues/47).
