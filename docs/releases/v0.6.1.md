# Anvil v0.6.1 — Directional Multi-Monitor Navigation and Window Placement

Anvil v0.6.1 is a maintenance/feature update to v0.6.0, making multi-monitor workflows easier to control from the keyboard and introducing preferred monitor/tag rules for new windows. Both enhancements preserve Anvil's lightweight, dwm-inspired design and existing shortcuts.

## What's new

### 1. Geometric monitor navigation ([#58](https://github.com/dme86/anvil/issues/58), [PR #60](https://github.com/dme86/anvil/pull/60))

- **Super + Left / Right / Up / Down** switches focus to the adjacent monitor in that *physical direction*.
- **Super + Shift + Arrow** moves the focused window to the monitor in that direction, assigns it to that monitor's currently visible tag, and follows it with keyboard focus.
- Monitor selection uses current logical output rectangles from the configured geometry, not the connector name or the order displays were plugged in. Horizontal, vertical and L-shaped setups are supported.
- No wraparound at the edge of a monitor layout. The existing cyclic **Super+, / Super+.** shortcuts (and their Shift-to-move variants) remain available.
- Direction bindings are configurable in `[keys]` through `output_left`, `output_right`, `output_up` and `output_down`.

### 2. Preferred output and tag for application windows ([#59](https://github.com/dme86/anvil/issues/59), [PR #61](https://github.com/dme86/anvil/pull/61))

- `[[window_rules]]` can now assign newly opened windows to an **output connector name** and a **one-based tag number**.
- `floating` is now optional; output-only, tag-only and existing floating-only rules can be combined. Rule matching still supports case-insensitive `app_id` and `title` globs; later matching explicit fields override earlier values.
- Rules are evaluated when the window's identity becomes known. Once its initial placement is determined, subsequent title changes, config reloads and manual window moves do not snap it back.
- If a preferred connector is **not connected**, a newly opened window falls back to an available focused monitor and **its currently visible tag**.
- If a monitor is **unplugged**, existing windows on that monitor migrate to the nearest remaining display and one of its visible tags; floating geometry is reset, and the compositor preserves focus where possible.
- **Reconnecting** the original monitor will *not* automatically move existing fallback windows back. Rules apply as usual to newly opened matching windows.
- If no displays are present, Anvil keeps the windows alive and maps them when a display comes back.

Example `config.toml`:

```toml
[keys]
output_left = "Left"
output_right = "Right"
output_up = "Up"
output_down = "Down"

[[window_rules]]
app_id = "firefox"
output = "DP-1"
tag = 1

[[window_rules]]
app_id = "discord"
output = "HDMI-A-1"
tag = 2
```

Discover connector names with `anvilctl output list`. A configured tag that is not currently visible on the target monitor can be revealed through the usual tag-switch shortcuts or the v0.6.0 window overview (`Super+Tab`).

## Installation

The Linux x86_64 release archive includes the `anvil` compositor, `anvilctl`, sample configuration, desktop session file, README, license and notices. Verify the archive using its adjacent SHA256 checksum.

```sh
cargo build --release
```

This release is tested by GitHub Actions (Rust tests, Clippy, nested Wayland/XWayland protocols and supported feature/size profiles). Real hardware DRM/KMS validation remains separately tracked in [#47](https://github.com/dme86/anvil/issues/47); this is still a pre-1.0 release.
