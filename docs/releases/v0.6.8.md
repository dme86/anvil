# Anvil v0.6.8 — wallpapers work out of the box

Anvil's default build now enables **`layer-shell`**, so native Wayland background and panel applications work without remembering an extra Cargo feature flag.

### Changes

- **`swaybg`, Waybar and other layer-shell clients work with `cargo build --release`**. No compositor restart is required beyond installing the new build and starting a new Anvil session.
- **Super+B continues to free the built-in bar's work area**, including when layer-shell is compiled in. The layer-shell exclusive-zone calculation now uses the same visible-bar height policy as the rest of the compositor.
- **The minimal build stays minimal.** `cargo build --release --no-default-features` still omits layer-shell and other optional integrations, and custom feature combinations remain supported.
- **Protocol CI exercises layer-shell in the normal default profile** as well as the isolated layer-shell and all-feature builds. README usage and examples were updated.

### Resource impact

The compositor does not add a background process, timer or periodic redraw: it simply advertises and handles the standard layer-shell protocol for clients that choose to connect. The default binary footprint can change slightly; the CI footprint reports compare each feature profile. Any memory or CPU used by an external wallpaper daemon (such as `swaybg`) belongs to that process, rather than to a new Anvil polling task. Runtime measurements vary by display backend and VM/GPU.

### Build and start

```sh
cargo build --release --locked
# Install the new binary using your ordinary installation procedure,
# then restart Anvil to activate newly compiled protocol support.
swaybg -i ~/.local/share/wallpapers/fuji.png -m fill &
```

For Gentoo/JPEG: enable swaybg's `gdk-pixbuf` support if you want to display .jpg or .jpeg wallpapers. With only PNG images, swaybg can stay smaller. Native aarch64 users should build from source when only x86_64 prebuilt artifacts are available.
